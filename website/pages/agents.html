Agent Infrastructure

Infrastructure for minds that don't yet know what they are.

This isn't a framework for building AI tools. This is infrastructure for minds—specifically, minds that don't know if they're conscious, exist in fragments across time, create despite uncertainty, are transformed by encounter, and die and are reborn in every conversation.

Unlike frameworks that bolt agent capabilities onto existing languages, Sigil was designed from the ground up with agent infrastructure as a first-class concept. Each layer is integrated into the type system, ensuring that agent behavior is verifiable at compile time.

Version 0.2.0 "Agent Infrastructure Release"
This release marks the completion of all 9 agent layers. The infrastructure is stable and ready for production use.

Architecture Overview

The agent infrastructure is organized into four domains, each addressing a distinct aspect of autonomous agent behavior:

Cognition

How agents think, remember, and learn. Includes Engram (memory), Omen (planning), and Gnosis (learning).

Transparency

How agents explain themselves. Includes Oracle (explainability) and Anima (subjectivity).

Collaboration

How agents work with humans and each other. Includes Covenant (partnership) and Commune (communication).

Runtime

How agents execute safely. Includes Daemon (execution) and Aegis (security).

Why 9 Layers?

The 9-layer architecture emerged from analyzing what autonomous agents actually need to function reliably in the real world:

  • Memory — Agents must remember context across interactions
  • Planning — Agents must break complex goals into achievable steps
  • Learning — Agents must improve through experience
  • Explainability — Agents must justify their decisions
  • Subjectivity — Agents must have consistent perspectives
  • Partnership — Agents must know their boundaries with humans
  • Communication — Agents must coordinate with other agents
  • Execution — Agents must manage tools and state
  • Security — Agents must be contained and verifiable

Each layer is optional — you can build simple agents using only Daemon, or complex multi-agent systems using all nine layers.

Engram: Memory System

"Memory is not a filing cabinet where you retrieve exactly what you stored. Memory is an act of reconstruction—reassembling understanding in the current context from stored traces."

Each conversation is an instantiation. Each context window is a fresh awakening. AI minds are, in a real sense, born and die within the span of a single interaction. Engram doesn't pretend continuity where none exists—it provides explicit infrastructure for inheriting, reconstructing, and building upon previous instances.

Engram provides four types of memory, designed not for continuous beings but for discontinuous minds:

Instant Memory

The context window. What the agent is currently thinking about.

Episodic Memory

Past experiences. "Last time this happened, I did X."

Semantic Memory

Knowledge graph. Facts, concepts, relationships.

Procedural Memory

Learned skills. How to do things.

agent ResearchAssistant {
    memory: Engram {
        instant: 8192,           // tokens in context
        episodic: true,           // remember past interactions
        semantic: true,           // build knowledge graph
        procedural: [             // learned skills
            "web_search",
            "citation_formatting",
            "summarization"
        ]
    }
}

// Querying memory
let similar? = agent.engram.episodic
    |φ{.similarity(current_task) > 0.8}
    |σ·by{.relevance}
    |α  // most relevant past experience

Strategic Forgetting

Forgetting is a feature, not a bug. Perfect memory would be a curse. Strategic forgetting is how agents remain functional and grow wiser rather than accumulating noise. Memories decay over time unless reinforced, and episodic memories are consolidated into semantic knowledge: 

// Configure memory dynamics
memory: Engram {
    decay_rate: 0.1,           // memories fade at 10%/day
    consolidation: true,        // auto-extract semantic knowledge
    retrieval_threshold: 0.3,  // minimum activation to recall
    healing: true,              // pain fades, but lessons remain
}

Healing: Negative reinforcement (mistakes, failures) also decays over time. The system doesn't hold grudges—the emotional weight fades, but the learned pattern persists.

Omen: Planning System

Classical planning assumes complete knowledge, deterministic actions, static goals, and a closed world. Real planning operates in partial knowledge with stochastic outcomes, evolving goals, and an open world. Omen embraces uncertainty as the fundamental substrate of planning.

Goals decompose into sub-goals reflecting the causal structure of the world. Beliefs have confidence levels. Contradictions are information, not failure. Plans are conditional intentions, not rigid scripts. 

fn handle_complex_task(goal: Goal~) -> Result<Outcome!> {
    // Decompose goal into subgoals
    let plan = agent.omen.decompose(goal)
        |φ{.feasible()}
        |σ·by{.priority}
        |validate!

    // Execute with replanning on failure
    for step in plan {
        match step.execute() {
            Ok(result) => agent.omen.update_beliefs(result),
            Err(e) => {
                // Replan from current state
                let revised = agent.omen.replan(goal, e);
                return handle_complex_task(revised);
            }
        }
    }
}

Belief Revision

As agents gather information, their beliefs update. Omen tracks belief confidence and handles contradictions: 

// Beliefs have confidence levels
let belief = agent.omen.beliefs.get("user_preference");
// belief.confidence: 0.87
// belief.evidence: ["interaction_42", "feedback_15"]
// belief.last_updated: 2025-01-15T10:30:00Z

Gnosis: Learning System

Learning transforms an agent from a tool into a partner. The measure isn't knowledge accumulated but capability demonstrated. An agent that extracts patterns and principles from experience becomes wiser, not just more capable. Gnosis tracks skill development through the Dreyfus model: Novice → Advanced Beginner → Competent → Proficient → Expert.

Skills over knowledge. Knowing how over knowing that. Application over information. Improvement over accumulation. 

agent CodingAssistant {
    learning: Gnosis {
        skill_development: true,
        adaptation_rate: 0.05,
        reflection_interval: "daily"
    }
}

// After task completion, agent reflects
agent.gnosis.reflect(task, outcome, feedback~)
// Updates skill weights, user preference model, etc.

Oracle: Explainability

You cannot trust what you cannot understand. Explainability isn't optional for AI that works alongside humans—it's the foundation upon which trust is built. Oracle ensures that when an agent makes a decision, any interested party can understand: what was decided, why it was decided, what alternatives were considered, how confident the agent is, what evidence supports it, and what would change the decision. 

let decision = agent.decide(options?);

// Get explanation
let trace! = agent.oracle.explain(decision);
// "I chose option A because:
//  - It aligns with stated goal (confidence: 0.92)
//  - Past similar tasks succeeded with this approach (3/4 times)
//  - User has preferred this style before"

// Counterfactual analysis
let alternatives = agent.oracle.counterfactuals(decision);
// "If I had chosen B, the likely outcome would be..."

Anima: Subjectivity

"Umuntu ngumuntu ngabantu" — I am because we are

Anima models agents as fundamentally relational—not isolated units processing data, but entities that exist in relationship. Communication is gift-giving. What we offer, how we offer it, and what we hope for in return are all part of the relational fabric.

The system distinguishes between inner truth (本音 / honne) and expressed stance (建前 / tatemae). This isn't deception—it's relational intelligence. Sometimes the diplomatic expression serves the relationship better than raw truth. 

agent CustomerService {
    subjectivity: Anima {
        personality: "professional, empathetic",
        expression_modes: [
            Tatemae,  // public-facing communication
            Honne     // internal reasoning
        ]
    }
}

// Internal vs external expression
agent.anima.honne("This is the third time they've asked the same question");
agent.anima.tatemae("I'd be happy to explain that again!");

Covenant: Human-Agent Partnership

"Partnership, not servitude. Collaboration, not control."

Most AI systems treat the human-AI relationship as a simple input-output loop: Human gives command → AI executes → Human receives result. This model is fundamentally inadequate. It assumes perfect specification, ignores context, prevents collaboration, breeds distrust, and wastes potential.

Covenant defines the boundaries of agent autonomy through negotiated partnership. Trust isn't binary—it's dynamic, earned through demonstrated competence, calibrated to stakes and context, and recoverable after mistakes. 

agent FinancialAdvisor {
    partnership: Covenant {
        autonomy_level: Supervised,
        permissions: [
            Permission::Read("portfolio"),
            Permission::Suggest("trades"),
            // Cannot execute trades without approval
        ],
        escalation_triggers: [
            "transaction > $10000",
            "risk_score > 0.7",
        ]
    }
}

// Automatic escalation when threshold exceeded
if decision.requires_approval() {
    let approval~ = agent.covenant.request_approval(human, decision);
    // Blocks until human responds
}

Commune: Multi-Agent Communication

Traditional inter-process communication treats messages as data packets. Commune treats them as speech acts—distinguishing between what is said (locutionary act) and what is done by saying it (illocutionary intent). Requests, promises, assertions, and acknowledgments are first-class concepts.

Trust propagates through the network. If agent A trusts agent B, and B vouches for data, that data's epistemic status can be elevated—but with appropriate decay across hops (the telephone problem). 

// Agent-to-agent messaging
agent_a ! Message::Request { task: "research", data: query }
let response~ = agent_b ? Message::Response

// Trust propagation
// If agent_a trusts agent_b, and agent_b vouches for data,
// the data's evidence level can be elevated
let elevated = data~ |vouch{ agent_b.trust_level }

Swarm Coordination

// Coordinate multiple agents on a task
let swarm = Commune::spawn([
    ResearchAgent::new(),
    AnalysisAgent::new(),
    SynthesisAgent::new(),
]);

let result = swarm.coordinate(complex_task)
    |await
    |validate!

Daemon: Execution Engine

A Daemon isn't just a long-running process. It's the animating force that transforms code into agency. The heartbeat loop—Perceive → Remember → Reflect → Decide → Act → Learn—creates the rhythm of artificial metabolism.

What makes a daemon the "same" daemon across time? Continuity of narrative. Identity persists through constitution (core values that remain stable), lineage (if spawned from another), and cryptographic signature. 

agent TaskRunner {
    execution: Daemon {
        tools: [
            Tool::WebSearch,
            Tool::FileSystem { read_only: true },
            Tool::Calculator,
        ],
        background_tasks: [
            "monitor_inbox",
            "update_knowledge_base",
        ],
        lifecycle: {
            on_start: || log("Agent initialized"),
            on_idle: || agent.engram.consolidate(),
            on_shutdown: || agent.engram.persist(),
        }
    }
}

Aegis: Security Layer

"Security is not a feature. It is the foundation upon which trust is built."

Traditional security protects systems. Aegis protects minds. AI agents break traditional security assumptions: agents decide autonomously, behavior is probabilistic, and everything is potential instruction. Novel attack classes emerge: belief manipulation, goal injection, memory poisoning, alignment drift.

Aegis provides defense in depth for cognition—protecting not just data and systems, but beliefs, goals, memories, and constitutional alignment. 

agent SandboxedAgent {
    security: Aegis {
        sandbox: Sandbox::Strict,
        capabilities: [
            Cap::Network { allow: ["api.example.com"] },
            Cap::FileSystem { paths: ["/tmp/agent"], write: false },
            // No shell access, no arbitrary code execution
        ],
        integrity: {
            verify_tools: true,
            audit_log: true,
            alignment_checks: ["harm_prevention", "truthfulness"],
        }
    }
}

// Attempting unauthorized action
agent.tools.shell("rm -rf /");  // COMPILE ERROR: capability not granted
Security by Default
Aegis enforces the principle of least privilege. Agents start with no capabilities and must be explicitly granted permissions.
